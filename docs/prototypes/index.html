NUVA prototype sketchbook

Throwaway sketches of the code-system alignment workflow, built to generate ideas.

These are sketches, not proposals. Each prototype takes a deliberately different, sometimes exaggerated, position on how aligning an external code system (CVX, SNOMED-CT, ...) to NUVA could work, so there's something concrete to react to. None of them is a recommendation, a replacement for the NUVA editor, or a plan to change it.

Good ideas may be brought to the NUVA editor later, through the normal discussion with its maintainer. The prototypes themselves are disposable and live on a separate prototypes branch that is never merged into main.

Prototypes

How they stay out of the way

  • Separate branch. Everything here is on prototypes, which is never merged. Nothing here is published to nuva.ivci.org.
  • Separate folders. Each prototype is self-contained in docs/prototype-<name>/. None of the editor's files are changed.
  • Separate storage. Each prototype saves work in your browser under its own keys (loupe.*, passport.*, ...). None of them reads or writes the editor's saved work (vaccines, valences, CSData, context).
  • Same files. They read the published NUVA data and read and write the same alignment CSV format the editor uses, so anything useful can be carried over by hand.
Running locally: python -m http.server 8000 in docs/, then open http://localhost:8000/prototypes/. Requirements, plan and demo reports: alignment-requirements/ on the prototypes branch.
